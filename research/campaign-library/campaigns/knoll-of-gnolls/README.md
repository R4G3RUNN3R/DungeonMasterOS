# Knoll of Gnolls

Status: `researching`

## Executive summary

`Knoll of Gnolls` is a low-level dungeon-delving adventure module by Infinite Fractal. A secret cave hidden among rolling knolls has been claimed by gnolls rumoured to be vicious and mutated, while secret magics and ancient creatures remain waiting underground.

The source advertises **over 40 keyed locations**, making this substantially larger than a typical one-page dungeon. It is designed for Embark but explicitly intended to be easy to adapt to other old-school systems. The creator built it for table usability with labelled referee maps, unlabeled player maps, a dedicated stat-block page, repeated stat references on relevant pages, and reference maps on every two-page spread.

Crucially, the creator explicitly states that **all game content is licensed under CC BY-SA 4.0**, with art separately identified as CC0, CC BY-SA 4.0 or public domain.

## Why this is a major DMOS candidate

This should be one of the first full dungeon modules we convert because it can test:
- hard map topology across 40+ rooms
- source-defined creature placement
- roaming/mutating gnoll state
- secret discovery and locked knowledge
- room-by-room state persistence
- player map/referee map separation
- old-school danger with free-text problem solving
- ShareAlike packaging at a meaningful size

## Level policy

The source says `low level` rather than publishing a D&D 5e numeric level on the public page. DungeonMasterOS must not translate that casually into `level 1` or `levels 1-3` until the actual stat blocks and hazards are extracted and converted.

## Blocking work before `templated`

1. Obtain/read the full current PDF.
2. Extract all 40+ keyed locations and exact map adjacency.
3. Extract all gnolls, ancient creatures, factions, magic, traps, treasure and stat blocks.
4. Determine what `mutated` actually means in the source and whether the rumour is true.
5. Separate referee-only map/secrets from player-visible geography.
6. Establish a tested D&D 5e level/party recommendation if providing 5e mode.
7. Search actual-play/community reports again after distinctive room/creature names are available.
8. Build dungeon-state and wandering/roaming-entity systems from source rather than generic dungeon assumptions.

# Leviathan - Location Register

Only locations/features supported by the public creator page or verified actual-play comments are included here. Exact station-map labels remain pending direct PDF extraction.

## Space Station
- Type: isolated orbital/space habitat
- Function: complete one-shot environment
- Initial state: PCs awaken here with amnesia
- Dynamic hazards: electrical failures, AI malfunctions, effects/pressure from intensifying coronal mass ejection
- Hard rule: the station is not secretly populated by an invented hostile creature simply because players expect one

## Central Computer / AI Interface
- Type: station-control / communication system
- Function: AI interaction and malfunction source
- Dynamic state: functioning -> increasingly malfunctioning -> potentially damaged/destroyed by players
- Actual-play evidence: a player shot the AI during its Leviathan-related monologue; scenario continued
- DMOS rule: critical information that must remain available after AI destruction requires alternate environmental/message delivery if the source permits it; do not make the interface invulnerable

## Airlock
- Type: station access / pressure boundary
- Actual-play evidence: an airlock breach became part of the players' theory that a creature would enter and attack
- DMOS rule: breach is an environmental/state problem, not proof of an external monster

## Sleep Pod / Cryopod Area
- Type: survival/hibernation equipment area
- Actual-play evidence: one player sealed themself in a cryopod-equivalent while the other guarded it
- DMOS rule: pods are valid player-interaction objects and can create improvised survival plans

## Laboratory / Beaker-associated area
- Type: station work/lab area
- Actual-play evidence: exploding beakers were one station problem the group elected not to address
- Canon confidence: medium until PDF verifies exact room/key name
- DMOS rule: retain as a station-problem category, not a hard named room until source extraction confirms it

## Solar Panel / External Power System
- Type: external station infrastructure
- Actual-play evidence: a solar-panel problem occurred and players chose not to prioritise it
- Canon confidence: medium until PDF verifies exact event wording
- DMOS rule: represents repairable external infrastructure; ignoring it may alter power/environment state without blocking the scenario by fiat

## Viewports
- Type: observation feature
- Evidence: actual-play/pamphlet feedback quotes a typo involving an impending cloud filling the viewports
- Canon confidence: high that viewports are part of source presentation; exact message wording intentionally not preserved here
- Function: communicates the worsening stellar phenomenon visually
